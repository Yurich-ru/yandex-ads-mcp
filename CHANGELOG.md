# Changelog

## 1.2.0 — 2026-08-06

### Несколько кабинетов Директа без агентства (`YD_DIRECT_TOKENS`)

Раньше второй кабинет Директа можно было подключить только через агентский `Client-Login`, что не работает для самостоятельных аккаунтов (например, субклиентов eLama: у каждого свой логин `e-XXXXXXXX`, а агентский токен есть только у eLama). Теперь:

- `YD_DIRECT_TOKENS=логин:токен,логин2:токен2` — свой OAuth-токен на каждый дополнительный кабинет; `YD_OAUTH_TOKEN` остаётся основным.
- Существующий аргумент `client_login` выбирает кабинет: если логин есть в `YD_DIRECT_TOKENS`, запрос идёт с его токеном и **без** заголовка `Client-Login`; любой другой логин — прежний агентский путь (основной токен + `Client-Login`). `YD_ALLOWED_LOGINS` применяется как раньше.
- Новый инструмент `yd_direct_accounts_get` — список всех доступных кабинетов с живой проверкой каждого токена через `Clients.get`.
- Формирование заголовков Директа сведено в одну функцию `direct_headers()` (раньше дублировалось в трёх местах).

Обратная совместимость: без `YD_DIRECT_TOKENS` поведение прежнее.

## 1.1.1 — 2026-08-06

### `yd_retargeting_lists_add`: поддержка сегментов Яндекс Аудиторий

Раньше инструмент не позволял сослаться на сегмент Аудиторий: Директ кодирует их в `ExternalId` как `id + 2 000 000 000`, а инструмент передавал id как есть и требовал `membership_life_span` (для сегментов он не нужен) — получалась ошибка 8800 «Объект не найден».

- Новое поле `audience_segment_id` в правилах — id сегмента Аудиторий как есть, кодировка добавляется автоматически.
- `membership_life_span` теперь необязателен (обязателен только для целей Метрики).
- Новое опциональное поле `type` (`RETARGETING` | `AUDIENCE`).
- В описании `goal_id` задокументирована полная кодировка `ExternalId`: цель Метрики — как есть; сегмент Метрики — `id + 1 000 000 000`; автосегмент — `id + 1 500 000 000`; сегмент Аудиторий — `id + 2 000 000 000`; интересы — строковый префикс `10`/`20`/`30` (краткосрочный/долгосрочный/любой).

Проверено на живом кабинете: грант сегмента из Аудиторий → условие ретаргетинга в Директе (`IsAvailable: YES`) → удаление.

## 1.1.0 — 2026-08-05

### Яндекс Аудитории — новый сервис (23 инструмента)

Модуль `tools_audience.py`, API `api-audience.yandex.ru/v1`:

- **Сегменты (11)**: список, загрузка CRM-данных (email/телефоны/ID устройств/ClientID) с подтверждением, переименование, удаление, пересчёт; создание lookalike, из Метрики, из AppMetrica, гео (окружности и полигоны), из пикселя.
- **Права доступа (3)**: выдача/отзыв доступа к сегменту по логину — так сегмент расшаривается в другой кабинет Директа.
- **Пиксели (5)**, **аккаунты и представители (4)**.

Требуется право «Яндекс Аудитории» в OAuth-приложении (после добавления — перевыпустить токен). Без него инструменты `yd_audience_*` возвращают 403 с подсказкой.

### Мульти-аккаунт: раздельные токены по сервисам

OAuth-токен привязан к одному Яндекс-аккаунту. Если Директ живёт в одном аккаунте, а Метрика/Аудитории — в другом, теперь можно задать `YD_METRIKA_TOKEN` и/или `YD_AUDIENCE_TOKEN`. Пустые переменные = используется `YD_OAUTH_TOKEN`, как раньше.

### Wordstat: поддержка API-ключа (`YC_API_KEY`)

Яндекс Облако перестало обменивать на IAM OAuth-токены, выпущенные после 01.06.2026 (для части приложений). Если задан `YC_API_KEY` (API-ключ сервисного аккаунта с ролью `search-api.executor`), Wordstat ходит с заголовком `Api-Key` без обмена на IAM. Пусто = прежний обмен OAuth→IAM.

Эндпоинт `wordstat/userInfo` (квота API) Яндекс, судя по всему, удалил — `yd_wordstat_user_info` возвращает 404; остальные инструменты Wordstat работают.

### Защитная обвязка

Классификатор мутирующих операций дополнен токенами `_confirm`, `_reprocess`, `_undelete` (используются только новыми инструментами Аудиторий). Инструменты Аудиторий подпадают под `YD_READONLY`/`YD_CONFIRM`, но не считаются инструментами Директа: `client_login` и `YD_ALLOWED_LOGINS` к ним не применяются.

### Зависимости: `mcp` запинен ниже 2.0

В августе 2026 вышел `mcp` SDK 2.0.0 с ломающим изменением низкоуровневого API (`Server.list_tools` удалён) — свежая установка по `requirements.txt` переставала запускаться независимо от версии этого проекта. Зависимость запинена: `mcp>=1.0.0,<2`. Если у вас сервер не стартует с `AttributeError: 'Server' object has no attribute 'list_tools'` — переустановите зависимости: `pip install -r requirements.txt --upgrade`.

### Обратная совместимость

Ломающих изменений нет:

- Существующие конфиги (только `YD_OAUTH_TOKEN`) работают без правок — все новые переменные опциональны и по умолчанию наследуют прежнее поведение.
- Ни один существующий инструмент не изменил имя, схему или классификацию (read-only/mutating, direct/не-direct).
- Новые инструменты `yd_audience_*` у пользователей без права «Яндекс Аудитории» возвращают понятную ошибку 403 и не влияют на остальные сервисы.
- Число инструментов выросло со 127 до 150 — клиенты с жёстким лимитом на количество tools (например, 128 у некоторых OpenAI-совместимых) могут потребовать фильтрации.
